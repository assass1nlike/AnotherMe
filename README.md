# AnotherMe

给科研工作者用的每日工作助手。核心想法是把“切换”当成一等数据：每次从一件事换到另一件事，都记下停在哪、回来后的下一步、为什么换。回到一件事时，助手会告诉你上次停在哪；积累一段时间后，能看出你换任务是因为累了还是卡住了。

## 功能

- 一个工作日从“开工”开始、到“收工”结束，可以跨过午夜，不依赖固定时间。
- 开工时助手参考上次的计划、收件箱和服务器上项目的最新进展，拟出今天要推进的 2 到 3 件事。
- 顶部的工作线按任务分段着色，切换点的标记表示原因，悬停可以看到当时停在哪、下一步是什么。
- 切换可以在界面里点，也可以在对话里随口说。
- 随手冒出的想法说一句“记一下……”就进收件箱，收工时再整理。
- 右侧显示服务器的 GPU 占用和 tmux 会话。助手可以只读地查看项目的 git 记录、`exps.md` 和 tmux 输出。
- 收工时统计每件事的实际用时、切换次数和原因，写复盘和明天计划的草稿。
- 支持 Claude 和 OpenAI 两种接口，可以配置中转地址。

## 项目档案

助手对每个项目的了解记在一份项目档案里（`data/projects/<项目>.md`），分为一句话、研究问题与假设、方法、目前的结论、正在跑的实验、卡点与待解决、决策记录、下一步、待确认、历史几节，结论都标明出处（exps.md 的哪一节、哪个 commit、哪天的对话）。档案有三个更新来源：

- 首次建档：通读服务器上的说明文档、完整的提交历史、整份 `exps.md`，以及在项目目录里开过的全部 Codex 会话。
- 增量同步：每次开工时在后台进行，只读上次同步以来的新提交、`exps.md` 的新改动（和本地缓存的上一版比对，包括还没提交的部分）和新的 Codex 对话。
- 收工沉淀：把当天对话和切换记录里关于这个项目的信息写进去。研究问题和方法不会被自动改动，相关的变化先写进“待确认”。

Codex 会话由 `workbench/codex_extract.py` 在服务器上提取（只用 Python 标准库），只取用户的发言和 Codex 的正式回复，跳过工具调用、工具输出、过程旁白和自动注入的上下文，按会话的工作目录归到项目。一个活跃项目几百 MB 的会话记录，提取后通常只剩十几万到几十万字。不想读取时，在 `config.toml` 里设 `codex = false`。

每次更新只改受影响的节，其余保持原文；改写前的版本存在 `data/projects/.history/`。对话时，今天计划里的项目会带上档案全文，其他项目只带一句话摘要；档案不够细时，助手会到服务器上搜索代码和实验记录、查 Codex 对话原文，或者查过往的对话。

档案也可以在界面右侧点项目名直接查看和编辑。

## 日期进度

双击 `progress.bat` 打开，是一个独立窗口（Edge 的应用模式，没有 Edge 时用 Chrome），和 AnotherMe 主程序互不影响，关掉窗口程序就退出。它读取研究目录（环境变量 `RESE`，没设置时用 `config.toml` 里 `[progress]` 的 `root`）下除 `skills`、`ideas`、`empirical` 外各子文件夹的 `determined.md`，可以直接编辑。

顶部的“墨”选择编辑日期，之后打的每个字都记为这一天写的，每天有自己的墨色；删掉的字直接消失。右栏列出各日期写了多少字，单击跳到该日期的下一处内容，双击换成这天的墨。正文右侧的细条是整份文档的墨迹图，标出各天写的内容在什么位置，点击可以跳转。鼠标停在文字上，会显示这段是哪天写的。选中一段已有文字后按 `Ctrl+D`、点底部浮出的按钮或右键，可以把它改标为当前日期，也可以清除日期，文字本身不变。停止输入 1.2 秒后自动保存，`Ctrl+Z`/`Ctrl+Y` 撤销和重做。

`determined.md` 本身保持纯 markdown，日期信息存在同目录的 `.determined.dates.json` 里。如果 md 在别处被改过，打开时顶部会提示，让你选改动部分记为哪天；如果两边同时有没保存的改动，会让你选保留哪边。开始使用前已有的内容显示为“开始记录前就有”。

## 角落清单

双击 `checklist.bat` 打开，是屏幕右上角的一个置顶小窗口，每条都是一行可以直接改的文字，独立运行，不需要开主程序。

- 写：底部“写一条”里回车添加；在某条里回车，在它下面新开一条；清空一条后再按退格，删掉这条。
- 排序：拖左边的把手，或在这一条里按 `Alt+↑`/`Alt+↓`。第一条左边有一道暖色，表示眼下最要紧的事。
- 收起和展开：收起时窗口完全隐藏，不占屏幕。按 `Ctrl+Alt+L`，或者把鼠标移到屏幕右上角停 0.4 秒，就会展开；点右上的“—”或按 `Esc` 收起。要求停留，是为了避免点最大化窗口的关闭按钮时误触。
- 再次运行 `checklist.bat` 不会开第二个，而是把已有的展开。

条目存在 `data/checklist/items.json`，每次增、删、改、移动都带着时间追加到 `history.jsonl`；改一条时，停手 2 秒或离开这一行才记一次，避免历史里全是半句话。主程序的助手每次对话都能看到当前条目，也能查编辑历史，但不会改它。角落、快捷键和宽度可以在 `config.toml` 的 `[checklist]` 里改（`corner` 取 `top-right`、`top-left`、`bottom-right`、`bottom-left`）。

## 使用

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy config.example.toml config.toml
```

在 `config.toml` 里填好模型的 key 和服务器，然后双击 `start.bat`，或运行 `.venv\Scripts\python -m workbench`，浏览器会打开 `http://127.0.0.1:8765`。

服务器通过本机 `~/.ssh/config` 里的 Host 名连接，需要已经配好免密登录。

## 结构

- `workbench/core.py`：数据和业务逻辑，存储在 `data/workbench.db`（SQLite），档案在 `data/profile.md`。
- `workbench/agent.py`：助手的提示词和工具。
- `workbench/memory.py`：项目档案的建立、同步和沉淀。
- `workbench/llm.py`：对两种模型接口的封装。
- `workbench/remote.py`：通过 ssh 只读地查看服务器。
- `workbench/server.py`：HTTP 接口。
- `web/`：界面。
- `progress/`：日期进度。`store.py` 负责日期的记录和对齐，`__main__.py` 是本地服务和窗口启动，`web/` 是界面。
- `checklist/`：角落清单。`store.py` 是条目和编辑历史，`__main__.py` 是窗口、快捷键和角落唤出，`web/` 是界面。

`data/` 和 `config.toml` 是个人数据，不进版本库。设置环境变量 `WORKBENCH_DATA` 可以换数据目录。
